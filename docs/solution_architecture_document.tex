\section{Problem Choice, Framing, and Assumptions}
I selected \textbf{Problem 1} because identifying viral promotional moments in microdramas presents a profound algorithmic challenge: the ``Lost in the Middle'' context problem. In vertical video formats (e.g., Kuku TV), viewer retention drops catastrophically if not captured within the first three seconds. Furthermore, the most viral dramatic hooks often bridge distant narrative setups and payoffs, such as a deception introduced in Episode 2 that is finally unmasked in Episode 15. A standard linear, episode-by-episode AI extraction loop completely misses this cross-episode cohesion. 

\textbf{Assumptions Made:} I assumed that standard vertical ad formats require promos to be strictly clamped between 20 and 60 seconds. I also assumed that production editors cannot use vague text summaries; they require precise, verifiable start and end timestamps mapped to specific scene dialogue to rapidly cut the final video.

\section{Applied AI Engineering \& Resilience Architecture}
To build a production-grade system rather than a fragile script, I engineered several core AI reliability mechanisms commonly utilized in enterprise environments:
\begin{itemize}
    \item \textbf{Dynamic Multi-Model Routing via LiteLLM:} To balance compute cost and reasoning capability, the system programmatically routes the massive ``macro skim'' tasks to a fast, high-context model (\texttt{gemini-1.5-flash}), while routing precise JSON parsing and timestamp extraction to a higher-reasoning model (\texttt{gemini-1.5-pro}). 
    \item \textbf{Automated Fallback Chains:} If a primary model fails due to a \texttt{503 Service Unavailable} error, the LiteLLM wrapper automatically intercepts the failure and cascades to fallback models (e.g., routing to Flash if Pro is overloaded) without crashing the pipeline.
    \item \textbf{Multi-Key Failover \& Pacing:} Free-tier APIs suffer from strict \texttt{429 Rate Limits} (e.g., 15 RPM). I built an \texttt{APIKeyPool} that monitors rate limits, instantly rotates to a healthy key upon failure, and injects adaptive sleep intervals between requests.
    \item \textbf{Autonomous JSON Repair:} Large Language Models occasionally append markdown backticks or trailing commas, breaking application parsers. I implemented a robust regex-based sanitization layer that intercepts malformed strings, locates the outermost JSON brackets, and parses the data safely. If it fails entirely, it prompts the LLM to self-correct.
\end{itemize}

\section{Complete Workflow Definition}
The system abandons the naive linear loop in favor of an optimized \textbf{Concept-Driven Map-Reduce Pipeline} executing in three distinct phases:

\textbf{Phase 1: Macro Director Skim (Concept Discovery)} \\
The engine compiles all 50 episodes into a single XML-tagged corpus. It sends this entire storyline to the LLM in one massive prompt. The model acts as an executive producer, tasked with identifying 10 to 15 highly viral, cross-episode promotional concepts, defining a 0--5 second ``Hook'' and a suspenseful ``Cliffhanger'' for each.

\textbf{Phase 2: Precision Concept Editor (The Map Step)} \\
Instead of re-sending the 500,000-character corpus repeatedly, the Python engine retrieves \textit{only} the specific screenplay text for the episodes involved in a given concept (e.g., fetching only Ep 2 and Ep 15). The LLM processes this micro-context to pinpoint precise scene timestamps. A deterministic code layer then mathematically clamps the duration to ensure it falls strictly between 20 and 60 seconds.

\textbf{Phase 3: Executive Cohesion Ranker (The Reduce Step)} \\
The engine aggregates all successfully extracted promos into a single JSON payload. The LLM evaluates them collectively as marketing instruments, prioritizing the emotional whiplash between the setup and the climax, and assigns a final 1-to-15 virality ranking.

\section{Performance: Outperforming the Baseline Solution}
A naive sequential architecture requires at least 50+ massive API calls (one per episode), resulting in high latency, massive token expenditure, and hallucinated context. 

My Map-Reduce workflow completes the entire series in just \textbf{12 to 17 API calls}: 1 call for the Skim, up to 15 targeted calls for Timestamp Extraction, and 1 final call for Ranking. By intentionally loading the heavy lifting onto the free-tier \texttt{gemini-1.5-flash} model and utilizing \texttt{gemini-1.5-pro} sparingly for precision tasks, the pipeline operates at near-zero cost while processing an entire series in under two minutes.

\section{Quality Checking, Honest Failures, and Improvements Needed}
The outputs were validated against the full input pack. The resulting JSON deliverables demonstrate strong narrative cohesion, correctly pairing setup moments with intense cut-to-black cliffhangers. However, I identified two primary limitations during testing:

\begin{itemize}
    \item \textbf{Context Degradation at Massive Scale:} Passing 50 episodes (approx. 500,000 characters) into the initial ``Director Skim'' works exceptionally well with Gemini Flash’s 1M-token window. However, scaling this to a 200+ episode mega-series will result in the ``Lost in the Middle'' phenomenon, where the model forgets mid-season plot points. \textit{Improvement needed:} Implement a sliding text-chunking strategy (e.g., 60,000-token overlapping windows) for regional concept discovery, followed by a deduplication step.
    \item \textbf{Timestamp Math Struggles:} Free-tier models occasionally struggle with rigid mathematical constraints (e.g., outputting timestamps that result in a 75-second clip despite strict instructions). \textit{Current Fix:} The code physically truncates the timestamps. \textit{Future Fix:} Swap the extraction task to a premium reasoning model (like \texttt{Claude 3.5 Sonnet} or \texttt{gpt-4o}), which exhibit far superior instruction-following for numerical constraints.
\end{itemize}

\section{The Prototype and Evaluator Overrides}
The application is deployed on Streamlit Community Cloud. It visualizes the top-ranked promotional cuts as clean dashboard cards with precise editing timestamps, and provides a centralized hub to download the raw JSON deliverables. Crucially, I built an \textbf{Evaluator API Override} into the sidebar. This allows recruiters to securely inject their own API keys and seamlessly override the free-tier default stack to evaluate the pipeline's performance using premium models of their choice.
